## 1. 目標

在現有的「預算分配」之外，新增「實際收支記帳」：

1. 每天記錄實際的支出和收入。
2. 每個月統計，並和當月預算比對：哪裡超出、哪裡有剩、下個月可以怎麼調整。
3. 用圖表呈現。
4. 先手動記帳；之後再支援載具（電子發票）匯入。

## 2. 名詞

| 名詞 | 意思 |
|---|---|
| **方案** | 現有的預算方案，例如「我的方案」、「加薪後」 |
| **大分類** | 例如生活費、居住、交通、儲蓄；對應方案裡的支出項目 |
| **小分類** | 大分類底下的細項，例如生活費 → 吃飯、飲料、日用品 |
| **紀錄** | 一筆實際支出或收入 |
| **固定收支** | 每月固定日期自動產生紀錄的設定，例如房租、薪水 |
| **月份** | 每月 1 號到月底 |

## 3. 分類（兩層、共用）

### 3.1 結構

```
生活費 🍙（大分類，支出類）
 ├ 吃飯（小分類）
 ├ 飲料
 └ 日用品
居住 🏠
 └ 房租
儲蓄 🐷（大分類，儲蓄類）
```

- **所有方案和記帳共用同一份分類清單**，比對時才對得起來。
- 大分類有：名稱、emoji、**類型**（支出／儲蓄）。
- 小分類只有名稱，屬於某個大分類；可以沒有小分類。
- 收入也有分類（例如薪水、兼職、股息），只有一層。

### 3.2 與預算方案的關係

- 方案裡的每個支出項目 = 一個大分類，再加上這個方案自己的 % 或金額。
- 在預算畫面新增支出項目時：選現有的大分類，或建立新的大分類。
- **改大分類的名稱或 emoji，所有方案都會一起改**（因為是同一個分類）。
- 方案的收入項目 = 收入分類，再加上金額。

### 3.3 分類管理

- 新增、改名、改 emoji、改類型、調整順序（拖曳）。
- 新增、改名、刪除小分類。
- **刪除大分類**：如果已經有紀錄或方案在使用，要先選一個大分類把它們搬過去。
- **刪除小分類**：底下的紀錄改成「只有大分類」。

## 4. 紀錄（記一筆）

| 欄位 | 必填 | 說明 |
|---|---|---|
| 類型 | ✅ | 支出／收入，預設支出 |
| 日期 | ✅ | 預設今天 |
| 金額 | ✅ | > 0；用計算機輸入 |
| 分類 | ✅ | 支出：大分類，或大分類＋小分類；收入：收入分類 |
| 備註 | | 自由文字，例如「珍奶」 |
| 來源 | 自動 | 手動／固定收支／載具匯入 |

- 每一筆都可以編輯、刪除。
- 🔶 記帳時，會優先列出**最近常用的分類**，加快輸入。

## 5. 每月明細

- 選擇月份（上個月／下個月）。
- 依日期分組，例如「10/24（五）」，顯示當天的每一筆紀錄和當天小計。
- 月份總覽：本月收入、本月支出、結餘。
- 可以用分類篩選，例如只看「生活費」。

## 6. 每月預算

### 6.1 每月指定一個方案

- 每個月份記住使用哪個預算方案。
- 新的月份**預設使用目前開啟的方案**，也可以手動更改。
- **月份結束後自動鎖定**：把當時的方案內容存成快照，之後修改或刪除方案，都不會影響過去月份的比對結果。
- 已鎖定的月份可以「重新套用方案」，需要二次確認。

### 6.2 預算金額怎麼算

- 🔶 用**方案裡的預算金額**比對，也就是方案收入 × %，或固定金額。實際收入多或少，不會讓預算跟著變。

## 7. 月統計與預算比對

### 7.1 支出比對（以大分類為單位）

每個支出類的大分類顯示：

| 預算 | 實際 | 差額 | 使用率 | 狀態 |
|---|---|---|---|---|
| 15,000 | 17,200 | −2,200 | 115% | 超支 |

- **超支**：使用率 > 100%。
- **花太快**（只有本月才判斷）：使用率 比「月份已過的比例」多 15 個百分點以上。
  - 例：今天 15 號，30 天的月份已過 50%；生活費已用 70% → 花太快。
- **正常**：其他情況。
- **預算外**：當月方案沒有的大分類也有支出時，另外列出。
- 點大分類可以展開，看各個小分類花了多少。

### 7.2 收入比對

- 預算收入（方案的收入合計）vs 實際收入（收入紀錄合計）。

### 7.3 儲蓄（做法 A：自動算）

- **實際儲蓄 = 實際收入 − 實際支出**，不需要另外記錄。
- 和預算的儲蓄目標比對（方案中「儲蓄類」大分類的合計）。
- 例：「儲蓄目標 9,480｜實際存下 6,200｜少存 3,280」。
- 當月還沒有任何收入紀錄時，🔶 用方案的預算收入估算，並標示「以預算收入估算」。

### 7.4 調整建議（月底或查看過去月份時）

- **超支的分類**：列出超出多少。
- **用得少的分類**：使用率 < 70%，提示「預算可能給太多」。
- 有超支、也有用得少的分類時，建議「把 A 多出的 N 元移給 B」。
- 🔶 第一版只顯示建議，不會自動修改方案；之後可以加「套用到方案」按鈕。

## 9. 固定收支

### 9.1 設定

| 欄位 | 例子 |
|---|---|
| 類型 | 支出／收入 |
| 名稱 | 房租 |
| 金額 | 13,000 |
| 分類 | 居住（＋小分類：房租） |
| 每月幾號 | 5；如果當月沒有這一天（例如 31 號），就用月底那天 |
| 記帳方式 | **自動記入**／**提醒我確認金額** |
| 開始月份 | 2026-11 |
| 啟用中 | 可以暫停 |

- 在預算畫面，以「固定金額」填寫的項目可以一鍵加入固定收支。

### 9.2 產生紀錄

- 網頁 App 沒辦法在背景執行，所以在**打開 App 時**檢查：
  - 這個月已過了設定的日期，而且還沒產生過 → 產生紀錄。
  - 好幾個月沒打開 → 把漏掉的月份一次補上。
- **自動記入**：直接產生紀錄，並提示「✅ 已自動記入：房租 13,000」。
- **提醒我確認**：列在「待確認」清單，例如「電費 本月金額？」；填好金額才記入，也可以選「這個月略過」。
- 產生的紀錄帶有「固定」標記，可以照常編輯或刪除；刪除後當月不會再產生。

## 10. 資料備份（第 1 階段一起做）

- **匯出**：把全部資料（方案、分類、紀錄、固定收支）存成一個檔案（JSON），檔名例如 `goldbud-backup-2026-10-24.json`。
- **匯入**：選擇備份檔，**取代**目前全部資料（需二次確認）。
- 🔶 每個月第一次打開時，提醒「上次備份是 N 天前」。

## 11. 資料結構（schemaVersion 2）

```ts
type AppData = {
  schemaVersion: 2;
  activePlanId: string;
  plans: Plan[];
  categories: Category[];          // 支出／儲蓄的大分類
  incomeCategories: IncomeCategory[];
  entries: Entry[];
  recurring: Recurring[];
  months: Record<string, MonthBudget>; // key："2026-10"
  lastBackupAt: string | null;
};

type Category = {
  id: string;
  name: string;
  emoji: string;
  kind: "expense" | "saving";
  subcategories: { id: string; name: string }[];
};

type IncomeCategory = { id: string; name: string };

type Plan = {
  id: string; name: string; createdAt: string; updatedAt: string;
  incomes: { id: string; categoryId: string; amount: number | null }[];
  expenses: { id: string; categoryId: string; mode: "percent" | "amount"; value: number | null }[];
};

type Entry = {
  id: string;
  type: "expense" | "income";
  date: string;               // "2026-10-24"
  amount: number;
  categoryId: string;         // 大分類或收入分類
  subcategoryId: string | null;
  note: string;
  source: "manual" | "recurring" | "import";
  recurringId: string | null;
  invoiceNo: string | null;   // 載具匯入時用來避免重複
  createdAt: string;
  updatedAt: string;
};

type Recurring = {
  id: string; type: "expense" | "income"; name: string; amount: number;
  categoryId: string; subcategoryId: string | null;
  day: number;                // 1–31
  mode: "auto" | "confirm";
  startMonth: string;         // "2026-11"
  active: boolean;
  skipped: string[];          // 被略過或刪除的月份，不再產生
};

type MonthBudget = {
  planId: string;
  locked: boolean;
  snapshot: Plan | null;      // 鎖定時的方案內容
};
```

### 11.1 從 v1 轉換

- 每個方案的支出項目，依**名稱**合併成大分類（同名就是同一個），emoji 沿用。
- 名稱包含「儲蓄」、「存」、「投資」的，類型設為儲蓄；其他設為支出。之後可以在分類管理修改。
- 收入項目依名稱合併成收入分類。
- 方案的支出和收入項目，改成指向對應的分類。
- 轉換前先自動備份舊資料（沿用現有的 backup 機制）。

### 11.2 容量

- 瀏覽器儲存空間約 5 MB；一筆紀錄約 200 bytes，大約可以存 2 萬筆以上（每天 10 筆、5 年），足夠使用。

## 12. 分階段

| 階段 | 內容 |
|---|---|
| **第 1 階段**（v2.0） | 兩層分類、手動記帳、每月明細、每月預算與鎖定、月統計與比對、長條圖＋圓餅圖、固定收支、備份匯出／匯入 |
| **第 2 階段** | 載具消費明細**匯入**：自動分類規則（例如「7-ELEVEN → 生活費／吃飯」，會從你的修正中學習）、用發票號碼避免重複。實際可下載的檔案格式到時再確認 |
| **第 3 階段** | 評估載具**自動同步**：需要向財政部申請 API、需要伺服器，也需要安全保管手機條碼驗證碼 |

## 13. 確定的決策

| 決策 | 內容 |
|---|---|
| 每月預算 | 每月指定一個方案，月份結束後鎖定成快照 |
| 分類 | 共用、兩層（大分類／小分類），每筆可以寫備註 |
| 月份 | 每月 1 號到月底 |
| 實際收入 | 要記錄，並和預算收入比對 |
| 儲蓄 | 做法 A：實際收入 − 實際支出，自動算出 |
| 固定收支 | 支援；自動記入或提醒確認 |
| 付款方式 | 不記錄 |

## 15. 之後討論 UI 時要決定的事

- 預算、記帳、統計三個區塊怎麼切換（例如底部分頁列）。
- 「記一筆」要多快完成：從打開 App 到記好，目標 3 次點擊以內。
- 分類管理、固定收支設定放在哪裡。
- 圖表的樣式要和現有的蠟筆、遊戲風格一致。
- 水豚在記帳和統計畫面的角色，例如月結時依結果換表情。
