# 第一部分：預算分配

## 1. 產品概述

- **目的**：輸入每月收入，用百分比或固定金額把收入分配到各個支出／儲蓄項目，讓財務規劃變得輕鬆好玩。
- **平台**：手機優先（mobile-first）網頁，用手機瀏覽器開啟即可；桌機也能正常顯示。
- **使用方式**：單一頁面，不需註冊登入，資料只存在使用者自己的瀏覽器。

## 2. 頁面結構（由上到下）

App 底部有分頁列「記帳｜統計｜＋｜預算｜更多」（B15）。預算頁由上到下：

1. 標題列
2. 方案標籤列，以及「這個方案是不是本月的預算」
3. 收入區塊
4. 支出區塊
5. 摘要列（固定在分頁列上方，含吉祥物）

## 3. 方案（多組）

- 頁面上方是可左右滑動的**方案標籤列**，例如：`我的方案`｜`加薪後`｜`＋`
- 每個方案各自擁有一份收入和支出清單。

| 功能 | 說明 |
|---|---|
| 新增 | 點「＋」建立新方案，內容為第 8 節的預設範例 |
| 複製 | 複製目前方案，方便比較不同情境 |
| 重新命名 | 點目前方案標籤的 ⋯ 選單 |
| 刪除 | 需二次確認；至少保留一組方案（只剩一組時刪除按鈕停用） |
| 切換 | 點標籤即切換；記住上次開啟的方案 |

## 4. 收入區塊

| 欄位 | 類型 | 規則 |
|---|---|---|
| 收入分類 | 選擇 | 共用的收入分類（B3），例如：薪水、股息、兼職；同一個方案裡不能重複 |
| 金額 | 數字 | ≥ 0，可有小數；空白視為 0。點擊開啟計算機輸入（見 5.5） |

- 「＋ 新增收入」：選一個收入分類（或新增），加在清單最後。
- 每列有刪除按鈕。
- 每列左側有拖曳把手 ⠿，可拖曳調整順序（見 5.6）。
- **收入總計** = 所有金額加總，即時更新。

## 5. 支出區塊

### 5.1 欄位

| 欄位 | 類型 | 規則 |
|---|---|---|
| 圖示 | emoji | 屬於大分類；在這裡改會所有方案一起改 |
| 大分類 | 選擇 | 共用的大分類（B3），例如：飲食、居住、儲蓄；同一個方案裡不能重複 |
| 百分比 % | 數字，可編輯 | 0～100，可有小數 |
| 金額 | 數字，可編輯 | ≥ 0。點擊開啟計算機輸入（見 5.5） |

### 5.2 % ⇄ 金額 雙向計算

- 填 %：金額 = 收入總計 × %
- 填金額：% = 金額 ÷ 收入總計
- **最後編輯的欄位是該列的「主值」**，以實線框標示；另一欄是虛線框。

收入總計改變時：

| 該列主值 | 結果 | 例子 |
|---|---|---|
| % | % 不變，金額重算 | 吃飯 30% |
| 金額 | 金額不變，% 重算 | 房租固定 13,000 |

- 收入總計為 0 時，以金額為主值的列，其 % 顯示「—」（不顯示錯誤）。

### 5.3 區塊小計

- **已分配**：% 合計與金額合計
- **未分配**：100% − 已分配 %，以及對應金額

### 5.4 分段與操作

- 支出卡片分成三段，依大分類的類型（B3.1）：**🏠 固定支出**、**🛒 變動支出**、**🐷 儲蓄／投資**。
- 每段標題右邊顯示小計（% 與金額）；沒有項目時顯示「還沒有固定支出」等提示。
- 點段落標題左邊的圖示可以換成其他 emoji（預設 🏠 🛒 🐷），統計頁和記帳頁一起換。
- 每段最下方有自己的「＋ 新增…」：只列出這個類型的大分類，在這裡新增的大分類就是這個類型。
- 要把項目換到別的段落：到「更多 → 分類管理」改它的類型，所有方案一起換。
- 每列刪除按鈕。
- 以固定金額填寫的支出項目，旁邊有 🔁，一鍵加入固定收支（B9）。
- 每列左側有拖曳把手 ⠿，可以在同一段裡拖曳調整順序（見 5.6）。

### 5.5 金額計算機

收入和支出的**金額欄位（NT$）**點下去時，不叫出手機鍵盤，而是從底部滑出簡易計算機，方便把好幾筆金額加總後再填入。

- 標題：「〔項目名稱〕的金額」，例如「薪水的金額」；還沒填名稱時顯示「收入金額」或「支出金額」。
- 顯示區：上方是算式（例如 `1,200 + 350 × 2`），下方大字是結果預覽。
- 按鍵：`0`～`9`、`00`、`.`、`+ − × ÷`、`=`、`C`（全部清除）、`⌫`（刪一格），以及最下方的「輸入」按鈕。
- 運算順序：先乘除、後加減（`1,200 + 350 × 2 = 1,900`）。
- 打開時顯示欄位目前的數字；這時直接按數字會取代它，按運算符號則接著算（例如 `+ 500`）。
- 按 `=`：算出結果，結果變成新的起點，可以繼續算。
- 按「輸入」：把結果填回欄位並關閉計算機。還沒按 `=` 也可以直接按「輸入」，會先算出結果。算式清空後按「輸入」，欄位會變成空白。
- 支出的金額經由計算機填入後，該列的主值變成「金額」。
- 錯誤（「輸入」按鈕停用）：除以 0 →「無法除以 0」；結果小於 0 →「金額不能是負數」。
- 結果保留到小數點後 2 位；欄位顯示時仍四捨五入到整數。
- 點計算機外面或往下關閉：不改變欄位。
- 電腦鍵盤也能操作：數字、`+ - * /`、`Enter`（=）、`Backspace`、`Esc`（關閉）。

### 5.6 拖曳排序

- 收入、支出每一列左側都有拖曳把手 ⠿。
- 按住把手上下拖曳，放開後順序就改好並自動儲存；只能在同一個區塊內移動。
- 拖曳中的那一列稍微浮起（陰影），其他列即時讓出位置。
- 拖到畫面上緣或下緣時，畫面會自動捲動。
- 只有按住把手才會拖曳，手指在其他地方滑動仍是正常捲動畫面。
- 鍵盤：把手取得焦點時，按 ↑ / ↓ 移動該列。

## 6. 摘要列（固定底部）

- 位置：和底部分頁列放在同一個固定區塊裡，疊在分頁列正上方，不會錯開或被蓋住；頁面內容會留出整個區塊的高度（包含 iPhone 下方的安全區）。
- 新增收入或支出後，畫面停在原處，新的那一列捲到看得到的地方。
- 顯示：收入總計｜已分配｜剩餘
- **分配進度條**：0 → 100% 逐漸填滿；超過 100% 的部分變紅色。
- 吉祥物＋狀態文字（見第 7 節）。
- 超過 100% 時**只顯示警告，不禁止輸入**。

## 7. 視覺風格

### 7.1 方向

可愛、有一點遊戲感，但**不幼稚**；用語維持一般用語。

| 元素 | 設計 |
|---|---|
| 配色 | 奶油色背景、柔和粉嫩色系；收入用**薄荷綠**，支出用**蜜桃橘**，進度用**柚子橘**，超支用柔和的紅（色碼見 7.4） |
| 字型 | 數字用圓潤的 **Nunito**；中文用系統字（蘋方等）粗體 |
| 卡片／按鈕 | 大圓角＋與水豚同色的咖啡粗外框＋厚底，按下有「壓下去」的回饋 |
| 進度條 | 類似遊戲能量條，填滿時有動畫 |
| 小互動 | 新增列時輕微彈跳；剛好分配到 100% 時灑彩帶 |

### 7.2 吉祥物：水豚（Capybara）

- 定位：**佛系、穩重、有點呆萌**，不走大眼睛閃亮亮的超可愛路線。
- 造型：簡單線條、低彩度咖啡色、表情變化小但看得出來。
- 畫風：參考 `design/references/capybara-style.webp`，是原創繪製，不照抄參考圖。
  - 蠟筆質感的深咖啡粗外框
  - 圓胖的麻糬身形、小圓耳、露出兩隻小腳
  - 小黑點眼睛、粉紅腮紅、深色鼻子區塊加上「Y」字鼻嘴
- 素材：`design/mascot/capybara-{sleep,calm,done,sweat}.svg`，由 `design/mascot/build.py` 產生；要改顏色或造型就改這個檔，再重新產生。

| 狀態 | 吉祥物 | 文字 |
|---|---|---|
| 尚未填收入 | 閉眼睡覺 | 「先填入收入吧」 |
| 已分配 < 100% | 平靜坐著 | 「還有 NT$ X 可以分配」 |
| 已分配 = 100% | 頭上頂著一顆柚子，泡溫泉 | 「分配完成！」 |
| 已分配 > 100% | 冒一滴汗 | 「超出 X%（NT$ X）」 |

### 7.3 用語

一般用語：「收入」、「支出分配」、「＋ 新增收入」、「＋ 新增支出」。

### 7.4 設計 tokens 與視覺稿

### 7.5 元件細節

- **主值欄位**：蜜桃橘實線框。
- **計算欄位**（非主值）：虛線框、文字顏色較淡；點一下就能編輯，編輯後變成主值。
- **拖曳把手**：淡咖啡色 ⠿，點擊範圍至少 44px 高。
- **計算機**：底部面板；數字鍵白底、運算鍵蜜桃橘淡色、`=` 柚子橘、「輸入」是滿版的柚子橘按鈕；按鍵都有厚底，按下會往下壓。
- **目前方案標籤**：柚子橘淡色底、咖啡粗框＋厚底；其他方案是淡框。
- **摘要列**：圓角面板固定在底部，水豚從左上角探出頭；狀態文字放在對話框裡。超支時對話框變成淡紅色。
- **刪除方案按鈕**：淡紅底、紅字。

## 8. 預設內容

第一次開啟時建立一組名為「我的方案」的範例；新增方案也使用相同比例（套用現有同名分類）。

- 收入：💰 薪水（金額空白）；收入分類另有 💼 兼職、📈 股息
- 支出：🍙 飲食 25%（吃飯、飲料）、🏠 居住 30%（房租、水電）、🚌 交通 5%（捷運、加油）、🎮 娛樂 10%、🐷 儲蓄 20%（儲蓄類）

## 9. 顯示與輸入規則

- 貨幣：NT$，金額加千分位（NT$ 47,800）。
- 計算出的金額四捨五入到整數；% 顯示到小數點後 1 位。
- % 欄位使用數字鍵盤（`inputmode="decimal"`）；點進欄位時自動全選，直接輸入就會取代舊數字。
- 金額欄位使用計算機（5.5），不叫出手機鍵盤。
- 輸入框字級至少 16px，避免 iPhone 點擊時自動放大畫面。
- 可點擊範圍至少 44 × 44 px。
- 底部面板裡的輸入框被點到、鍵盤彈出時，面板會移到鍵盤上方，不會被蓋住。
- 快速點兩下不會放大畫面（連按計算機鍵時特別重要）；雙指縮放仍然可以用。
- 不接受負數；非數字輸入忽略。

## 10. 資料儲存

- 存在瀏覽器 localStorage，每次修改自動儲存。
- 資料**不上傳**到任何伺服器。
- 「更多」頁提供「清除全部資料」（需二次確認，清除後回到預設範例）。
- 已知限制：換手機、換瀏覽器或清除瀏覽器資料後，資料會消失；請用「備份與還原」（B10）。

### 10.1 資料結構

見 B11（schemaVersion 3）。v1 的資料第一次開啟 v2.0.0 時會自動轉換，轉換前先在瀏覽器另存一份原始資料（`goldbud-backup-v1`）。

## 11. 加到手機主畫面與離線使用

- 支援「加入主畫面」（iPhone Safari）和「加到主畫面／安裝應用程式」（Android Chrome）。
- 從主畫面打開時全螢幕顯示，沒有瀏覽器網址列（`display: standalone`）。
- 桌面圖示：奶油色底，加上頭頂柚子的水豚（`design/icons/`），由 `design/mascot/build.py` 和 `design/icons/render.sh` 產生。
- App 名稱：**小金芽**（英文 Goldbud）。
- 第一次打開後，App 的檔案會存在手機上，**沒有網路也能打開**（`sw.js`）。
- 發布新版後，下次打開 App 時會在背景下載新版，再下一次打開就是新版。

# 第二部分：實際收支記帳

## B1. 目標

在現有的「預算分配」之外，新增「實際收支記帳」：

1. 每天記錄實際的支出和收入。
2. 每個月統計，並和當月預算比對：哪裡超出、哪裡有剩、下個月可以怎麼調整。
3. 用圖表呈現。
4. 先手動記帳；之後再支援載具（電子發票）匯入。

## B2. 名詞

| 名詞 | 意思 |
|---|---|
| **方案** | 現有的預算方案，例如「我的方案」、「加薪後」 |
| **大分類** | 例如生活費、居住、交通、儲蓄；對應方案裡的支出項目 |
| **小分類** | 大分類底下的細項，例如生活費 → 吃飯、飲料、日用品 |
| **紀錄** | 一筆實際支出或收入 |
| **固定收支** | 每月固定日期自動產生紀錄的設定，例如房租、薪水 |
| **月份** | 每月 1 號到月底 |

## B3. 分類（兩層、共用）

### B3.1 結構

```
生活費 🍙（大分類，支出類）
 ├ 吃飯（小分類）
 ├ 飲料
 └ 日用品
居住 🏠
 └ 房租
儲蓄 🐷（大分類，儲蓄類）
```

- **所有方案和記帳共用同一份分類清單**，比對時才對得起來。
- 大分類有：名稱、emoji、**類型**：
  - **固定支出**：每月金額差不多，例如房租、管理費、電話網路、訂閱。
  - **變動支出**：每月會變動，例如吃飯、交通、娛樂。
  - **儲蓄／投資**：不算支出，例如儲蓄、定存、投資股票。
- 小分類只有名稱，屬於某個大分類；可以沒有小分類。
- 收入也有分類（例如薪水、兼職、股息），只有一層。

### B3.2 與預算方案的關係

- 方案裡的每個支出項目 = 一個大分類，再加上這個方案自己的 % 或金額。
- 在預算畫面新增支出項目時：選現有的大分類，或建立新的大分類。
- **改大分類的名稱或 emoji，所有方案都會一起改**（因為是同一個分類）。
- 方案的收入項目 = 收入分類，再加上金額。

### B3.3 分類管理

- 新增、改名、改 emoji、改類型、調整順序（拖曳）。
- 新增、改名、刪除小分類。
- **刪除大分類**：如果已經有紀錄或方案在使用，要先選一個大分類把它們搬過去。
- **刪除小分類**：底下的紀錄改成「只有大分類」。

## B4. 紀錄（記一筆）

| 欄位 | 必填 | 說明 |
|---|---|---|
| 類型 | ✅ | 支出／收入，預設支出 |
| 日期 | ✅ | 預設今天 |
| 金額 | ✅ | > 0；用計算機輸入 |
| 分類 | ✅ | 支出：大分類，或大分類＋小分類；收入：收入分類 |
| 備註 | | 自由文字，例如「珍奶」 |
| 來源 | 自動 | 手動／固定收支／載具匯入 |

- 每一筆都可以編輯、刪除。
- 記帳時，會優先列出**最近常用的分類**，加快輸入。

## B5. 每月明細

- 選擇月份（上個月／下個月）。
- 依日期分組，例如「10/24（五）」，顯示當天的每一筆紀錄和當天小計。
- 月份總覽：本月收入、本月支出、結餘；有預算時另外顯示「固定支出」和「變動支出」各自的實際 / 預算。
- 可以用分類篩選，例如只看「生活費」。

## B6. 每月預算

### B6.1 每月指定一個方案

- 每個月份記住使用哪個預算方案。
- 新的月份**預設使用目前開啟的方案**，也可以手動更改。
- **月份結束後自動鎖定**：把當時的方案內容存成快照，之後修改或刪除方案，都不會影響過去月份的比對結果。
- 已鎖定的月份可以「重新套用方案」，需要二次確認。

### B6.2 預算金額怎麼算

- 用**方案裡的預算金額**比對，也就是方案收入 × %，或固定金額。實際收入多或少，不會讓預算跟著變。

## B7. 月統計與預算比對

### B7.1 支出比對（以大分類為單位）

每個支出類的大分類顯示：

| 預算 | 實際 | 差額 | 使用率 | 狀態 |
|---|---|---|---|---|
| 15,000 | 17,200 | −2,200 | 115% | 超支 |

- **超支**：使用率 > 100%。
- 分成「固定支出」、「變動支出」、「預算外」三段，每段標題顯示「實際 / 預算」小計。
- **花太快**（只有本月、只有**變動支出**才判斷）：使用率 比「月份已過的比例」多 15 個百分點以上。固定支出本來就是一次付清，不判斷速度，進度條也不畫今天線。
  - 整個月的「花太快」也只看變動支出的合計；「超支」看全部支出。
  - 例：今天 15 號，30 天的月份已過 50%；生活費已用 70% → 花太快。
- **剛好用完**（實際 = 預算，例如月初付清的房租）算正常，不算花太快（D-047）。
- 判斷「花太快」時，先把這個月已記入的固定收支從實際和預算扣掉，只看日常開銷的速度（D-047）。
- **正常**：其他情況。
- **預算外**：當月方案沒有的大分類也有支出時，另外列出。
- 點大分類可以展開，看各個小分類花了多少。

### B7.2 收入比對

- 預算收入（方案的收入合計）vs 實際收入（收入紀錄合計）。

### B7.3 儲蓄（做法 A：自動算）

- **實際儲蓄 = 實際收入 − 實際支出**，不需要另外記錄。
- 和預算的儲蓄目標比對（方案中「儲蓄類」大分類的合計）。
- 例：「儲蓄目標 9,480｜實際存下 6,200｜少存 3,280」。
- 當月還沒有任何收入紀錄時，用方案的預算收入估算，並標示「以預算收入估算」。

### B7.4 調整建議（月底或查看過去月份時）

- **超支的分類**：列出超出多少。
- **用得少的分類**：變動支出的使用率 < 70%，提示「預算可能給太多」（固定支出不提醒，例如這個月剛好還沒繳）。
- 有超支、也有用得少的分類時，建議「把 A 多出的 N 元移給 B」。
- 第一版只顯示建議，不會自動修改方案；之後可以加「套用到方案」按鈕。

## B9. 固定收支

### B9.1 設定

| 欄位 | 例子 |
|---|---|
| 類型 | 支出／收入 |
| 名稱 | 房租 |
| 金額 | 13,000 |
| 分類 | 居住（＋小分類：房租） |
| 每月幾號 | 5；如果當月沒有這一天（例如 31 號），就用月底那天 |
| 記帳方式 | **自動記入**／**提醒我確認金額** |
| 開始月份 | 2026-11 |
| 啟用中 | 可以暫停 |

- 在預算畫面，以「固定金額」填寫的項目可以一鍵加入固定收支。
- 新增時如果這個月的日期已經過了，詢問「現在記入」或「從下個月開始」，避免和已經手動記的重複（D-048）。

### B9.2 產生紀錄

- 網頁 App 沒辦法在背景執行，所以在**打開 App 時**檢查：
  - 這個月已過了設定的日期，而且還沒產生過 → 產生紀錄。
  - 好幾個月沒打開 → 把漏掉的月份一次補上。
- **自動記入**：直接產生紀錄，並提示「✅ 已自動記入：房租 13,000」。
- **提醒我確認**：列在「待確認」清單，例如「電費 本月金額？」；填好金額才記入，也可以選「這個月略過」。
- 產生的紀錄帶有「固定」標記，可以照常編輯或刪除；刪除後當月不會再產生。

## B10. 資料備份（第 1 階段一起做）

- **匯出**：把全部資料（方案、分類、紀錄、固定收支）存成一個檔案（JSON），檔名例如 `goldbud-backup-2026-10-24.json`。
- **匯入**：選擇備份檔，**取代**目前全部資料（需二次確認）。
- 每個月第一次打開時，提醒「上次備份是 N 天前」（超過 30 天）；從沒備份過的話，最早的紀錄滿 7 天才提醒（D-049）。可以按 ✕ 關掉當月的提醒。

### B11.1 從 v1 轉換

- 每個方案的支出項目，依**名稱**合併成大分類（同名就是同一個），emoji 沿用。
- 名稱包含「儲蓄」、「存」、「投資」的，類型設為儲蓄；其他設為支出。之後可以在分類管理修改。
- 收入項目依名稱合併成收入分類。
- 方案的支出和收入項目，改成指向對應的分類。
- 轉換前先自動備份舊資料（沿用現有的 backup 機制）。
- v1 會接著轉成 v3（見下方）。

### B11.1.1 從 v2 轉換到 v3（v2.1.0）

- v2 的「支出」類大分類分成固定或變動：在任何方案裡用**固定金額**填的、或有支出類**固定收支**的 → 固定支出；其他 → 變動支出。儲蓄類不變，顏色不變。
- 轉換前備份成 `goldbud-backup-v2`。之後可以在分類管理調整。

### B11.2 容量

- 瀏覽器儲存空間約 5 MB；一筆紀錄約 200 bytes，大約可以存 2 萬筆以上（每天 10 筆、5 年），足夠使用。

## B13. 確定的決策

| 決策 | 內容 |
|---|---|
| 每月預算 | 每月指定一個方案，月份結束後鎖定成快照 |
| 分類 | 共用、兩層（大分類／小分類），每筆可以寫備註 |
| 月份 | 每月 1 號到月底 |
| 實際收入 | 要記錄，並和預算收入比對 |
| 儲蓄 | 做法 A：實際收入 − 實際支出，自動算出 |
| 固定收支 | 支援；自動記入或提醒確認 |
| 付款方式 | 不記錄 |
